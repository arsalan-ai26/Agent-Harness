Surfaces: embedding, protocols and channels

The same harness can sit behind a terminal, an editor, a web app, Slack and a GitHub issue. Getting there means separating the harness from its front doors: a session API, an event stream, a protocol for editors, and channels that turn outside messages into sessions. This chapter reads how fx embeds itself in scripts, editors and apps, how eve's channels work, how nanocode runs one Rust core in many languages and how Pi exposes its modes, then builds a session server with a GitHub channel. It closes Stage 4.

Before you start: skip check
  1. A web client loses its connection mid-turn. How does it catch up without missing events?
  2. What is the Agent Client Protocol (ACP) for?
  3. Why must a GitHub channel check who wrote a comment?
Answers
  1. Every event has a sequence number in a stored log; the client reconnects with the last number it saw and the server replays the rest.
  2. A standard way for editors to talk to coding agents over stdio, so one agent works in many editors without per-editor plugins.
  3. Public comments are untrusted input. Anyone could ask the agent to run privileged tools; only verified collaborators may start sessions with write access.

2. Code tour

fx: built to be embedded

fx's README lists three surfaces besides the terminal: fx ask for one request from a script or CI job (--json for structured output, --resume to continue a saved session); fx acp for editors and other Agent Client Protocol clients over stdio (src/acp/); and libfx, the agent core as a JavaScript library built both as a native Node.js addon and as WebAssembly, where createFxAgent() runs an agent with your own tools, MCP clients and skills and createFxTerminal() embeds the fx terminal (sdk/, sdk/NAPI.md for the security model). Vercel's AI SDK added an fx harness adapter, so apps can run fx as one option behind a common harness API. Vercel Labs describes fx as built for people building agent infrastructure more than for people wanting another chat window.

eve: channels as adapters

eve's README states the split: the channel normalizes inbound transport, applies auth and delivery policy and owns channel-local addresses; the harness does one unit of work and returns { session, next }. src/public/channels/ ships HTTP (on by default), Slack, Discord, Teams, Telegram, Twilio, GitHub, Linear and even MCP; defineChannel adds your own. A Slack thread or an issue is an address that maps to one session. eve has a conformance test kit for channels (src/internal/testing/channel-conformance/) and an ACP adapter (src/acp/adapter.ts).

nanocode: one core, many languages

Every reusable nanocode crate builds for native and wasm32-unknown-unknown. Bindings live in separate repos: TypeScript as one WebAssembly module (nanocode-ts), Swift for macOS and iOS, and C for a game engine or any host (libnanocode). A WASM embedder installs one host object that supplies scheduling, sleeps, clocks and secure random bytes. Live views (crates/runtime/live) fold the event log into diffs shared by every subscribed socket.

Pi: modes and composition

Pi runs interactively, in print or JSON mode, over RPC and as an SDK, and OpenClaw embeds it as its engine. packages/chord is a standalone application-composition runtime (services, replicated state, RPC, plugins) that Pi Durable builds on; Cloudflare's Agents SDK wraps Pi Durable as PiHarness.

4. Research and the Chinese view

  • The harness boundary moves. The Dive into Claude Code paper lists "where, when, what and with whom the agent acts" as an open design direction; surfaces are how that boundary moves.
  • Enterprise convergence. Stripe, Ramp and Coinbase independently built internal agents triggered from Slack and GitHub; an Aliyun article lists many entry points (Slack, GitHub, Feishu) as one of the problems that forced the same architecture (Aliyun).
  • Chinese desktop agents. Alibaba's QoderWork, launched Jan 2026, reached several hundred thousand users, with close to 80% starting three or more tasks a day (36Kr): the same harness idea, delivered as a desktop surface.

5. Build: a session server and a GitHub channel

"""One harness, many front doors: a session server with an event stream, plus a GitHub channel."""
import asyncio, hashlib, hmac, json, os, uuid
from fastapi import BackgroundTasks, FastAPI, Header, HTTPException, Request
from fastapi.responses import StreamingResponse

app = FastAPI()
SESSIONS: dict[str, dict] = {}        # in production: the Chapter 11 journal, not a dict

def run_turn(session_id: str, text: str, emit):
    """Replace with your harness. emit(event) is called for text deltas, tool calls and the final reply."""
    emit({"type": "turn.started"})
    emit({"type": "text", "delta": f"(working on: {text})"})
    emit({"type": "turn.completed", "reply": f"done: {text}"})

def emitter(session_id):
    s = SESSIONS[session_id]
    def emit(event):
        event = {"seq": len(s["events"]), **event}
        s["events"].append(event)                  # the log is the source of truth; clients replay from any seq
    return emit

@app.post("/sessions")
def create_session(body: dict | None = None):
    sid = uuid.uuid4().hex[:12]
    SESSIONS[sid] = {"events": [], "busy": False, "address": (body or {}).get("address")}
    return {"session_id": sid}

@app.post("/sessions/{sid}/messages")
def send(sid: str, body: dict, tasks: BackgroundTasks):
    s = SESSIONS.get(sid)
    if s is None:
        raise HTTPException(404)
    if s["busy"]:                                  # queue as steering instead of starting a second turn
        s["events"].append({"seq": len(s["events"]), "type": "steering.queued", "text": body["text"]})
        return {"queued": True}
    s["busy"] = True
    def work():
        try: run_turn(sid, body["text"], emitter(sid))
        finally: s["busy"] = False
    tasks.add_task(work)
    return {"accepted": True}

@app.get("/sessions/{sid}/events")
async def events(sid: str, after: int = -1, follow: bool = True):
    """Server-sent events. A client that reconnects passes the last seq it saw and misses nothing."""
    if sid not in SESSIONS: raise HTTPException(404)
    async def stream():
        seq = after
        while True:
            for e in SESSIONS[sid]["events"][seq + 1:]:
                seq = e["seq"]
                yield f"id: {seq}\ndata: {json.dumps(e)}\n\n"
            if not follow or (SESSIONS[sid]["events"] and SESSIONS[sid]["events"][-1]["type"] == "turn.completed"
                              and not SESSIONS[sid]["busy"]):
                return
            await asyncio.sleep(0.2)
    return StreamingResponse(stream(), media_type="text/event-stream")

# ---- a channel: GitHub issue comments start or continue a session -------------------------------
def verify(secret: str, body: bytes, signature: str | None) -> bool:
    expected = "sha256=" + hmac.new(secret.encode(), body, hashlib.sha256).hexdigest()
    return bool(signature) and hmac.compare_digest(expected, signature)

@app.post("/channels/github")
async def github(request: Request, tasks: BackgroundTasks, x_hub_signature_256: str | None = Header(None)):
    raw = await request.body()
    if not verify(os.environ.get("GITHUB_WEBHOOK_SECRET", ""), raw, x_hub_signature_256):
        raise HTTPException(401, "bad signature")
    ev = json.loads(raw)
    comment = ev.get("comment", {}).get("body", "")
    if "@harness" not in comment or ev.get("comment", {}).get("author_association") not in ("OWNER", "MEMBER", "COLLABORATOR"):
        return {"ignored": True}                   # only trusted users may start privileged work
    address = f"{ev['repository']['full_name']}#{ev['issue']['number']}"   # one session per issue
    sid = next((k for k, v in SESSIONS.items() if v["address"] == address), None) or create_session({"address": address})["session_id"]
    return send(sid, {"text": comment.replace("@harness", "").strip()}, tasks)

Wiring:

  • Replace run_turn with your durable harness from Chapter 11, calling emit for text deltas, tool calls and the reply. Store events in the journal, not in memory.
  • Make your CLI a client: create a session, post messages, read /events. Now the terminal is just one surface.
  • Expose the server (a small VM, or a tunnel), add the webhook to your repo with a secret, and comment @harness on an issue. Post replies back with the GitHub API from the trusted process only.
