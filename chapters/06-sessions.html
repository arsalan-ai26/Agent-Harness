Sessions, state and memory

A session is what lets you close the terminal and come back. State is what the agent knows is true right now. Memory is what it should still know next week. Harnesses mix these up at their cost. This chapter reads Pi's tree-shaped session files, fx's resumable sessions, eve's state and memory slots and nanocode's stores, then builds an append-only session tree with branching, resume and a memory slot that compaction can never touch. It closes Stage 2.

Before you start: skip check
  1. What is the difference between history and memory?
  2. Why store a session as a tree instead of a list?
  3. Why should memory stay outside the conversation history?
Answers
  1. History is what happened in this session (messages, tool calls). Memory is selected knowledge that should carry into future sessions.
  2. So you can go back to an earlier point and try another approach without deleting the first attempt or dragging its detours through the context.
  3. If it lives in history, compaction may summarize it away or distort it. Outside, it is recalled fresh every turn.

2. Code tour

Pi: sessions are append-only trees

The comment on SessionManager in packages/coding-agent/src/core/session-manager.ts says it best: sessions are append-only trees stored in JSONL files; each entry has an id and parentId; a leaf pointer tracks the current position; appending creates a child of the leaf; branching moves the leaf to an earlier entry, so new branches never modify history. buildSessionContext() walks from the root to the leaf and applies compaction summaries on the way.

The entry types show what a session must record beyond messages: model_change, thinking_level_change, usage, compaction, branch_summary, label (bookmarks), custom (extension state), context_edit. A version-1 to version-2 migration added the tree, a reminder that session formats need versioning. Users drive it with /tree, /fork and /clone, all branches in one file.

fx: resumable by project

fx saves conversations under ~/.fx/sessions/; fx -c picks up the last session in the current project and fx ask --resume continues one from a script. When fx compacts, the full text stays on disk where the agent can look it up (src/core/session/, src/core/session_manager/, src/core/compactor/records.zig).

eve: session, turn, step; state; memory slots

eve nests work in session, turn and step, and stores typed session values with defineState. Memory is separate (docs/memory/index.mdx): each slot is a file in agent/memory/ that names a provider (built-in file memory on Vercel Blob, or Supermemory, Upstash, your own) and a scope (for example per signed-in caller). On every turn eve resolves the scope, asks the provider to recall, gives the model the provider's tools as <slot>__<tool>, and asks it to capture after the turn. Recalled content enters as user messages labeled with the slot, never as system instructions, and the summarizer never sees it.

nanocode: stores you choose

crates/integrations/store-jsonl writes one append-only file per session (the CLI default). store-sql runs the same records over SQLite, Postgres or a host's own database, and on WASM over Durable Objects or D1. Branches live in crates/runtime/durability. Content-addressed blobs (crates/integrations/s3) keep large payloads out of rows.

4. Research and the Chinese view

  • Persistence is open research. The Dive into Claude Code paper lists memory and long-term human-agent relationships among its six open directions (arXiv 2604.14228).
  • Artifacts beat chat history. Anthropic's long-running harness persists progress in claude-progress.txt, a feature list and git commits, so each new session can rebuild state without the old conversation.
  • Chinese framing. OpenHarness's code walkthrough splits a harness into Brain (model calls), Hands (tools) and Session (memory) layers (CSDN); the Code as Agent Harness survey counts repository state and commit history as part of the harness's stateful medium.

5. Build: a session tree and a memory slot

"""Sessions as append-only JSONL trees (Pi's design), plus a memory slot that lives outside history (eve's design)."""
import json, os, time, uuid
from pathlib import Path

SESSIONS = Path.home() / ".harness" / "sessions"

class Session:
    """Every entry has id and parent_id. The leaf is the current position; appending adds a child of the leaf.
    Branching moves the leaf back. History is never rewritten."""
    def __init__(self, path: Path):
        self.path, self.entries, self.leaf = path, {}, None
        if path.exists():
            for line in path.read_text().splitlines():
                e = json.loads(line)
                if e["type"] == "leaf":                 # leaf moves are entries too, so a reload restores the position
                    self.leaf = e["to"]
                else:
                    self.entries[e["id"]] = e
                    self.leaf = e["id"]

    @classmethod
    def new(cls, cwd: str):
        SESSIONS.mkdir(parents=True, exist_ok=True)
        s = cls(SESSIONS / f"{time.strftime('%Y%m%d-%H%M%S')}-{uuid.uuid4().hex[:6]}.jsonl")
        s._write({"type": "session", "cwd": cwd, "id": uuid.uuid4().hex[:12], "parent_id": None})
        return s

    @classmethod
    def latest(cls, cwd: str):
        """Resume the newest session started in this directory (fx -c, pi --continue)."""
        for p in sorted(SESSIONS.glob("*.jsonl"), reverse=True):
            first = json.loads(p.open().readline())
            if first.get("cwd") == cwd:
                return cls(p)
        return None

    def _write(self, entry):
        with self.path.open("a") as f:                  # append only; one line per entry
            f.write(json.dumps(entry, default=str) + "\n")
            f.flush(); os.fsync(f.fileno())
        if entry["type"] == "leaf":
            self.leaf = entry["to"]
        else:
            self.entries[entry["id"]] = entry
            self.leaf = entry["id"]

    def append(self, kind: str, **data) -> str:
        """kind: 'message', 'checkpoint' (from compaction), 'model_change', 'label' ..."""
        entry = {"type": kind, "id": uuid.uuid4().hex[:12], "parent_id": self.leaf, "ts": time.time(), **data}
        self._write(entry)
        return entry["id"]

    def branch(self, entry_id: str):
        """Continue from an earlier entry. The old path stays in the file as a sibling branch."""
        assert entry_id in self.entries
        self._write({"type": "leaf", "to": entry_id})

    def path_to_leaf(self):
        out, cur = [], self.leaf
        while cur:
            e = self.entries[cur]
            out.append(e)
            cur = e["parent_id"]
        return out[::-1]

    def messages(self):
        """Messages the model sees: start at the last checkpoint on the path, then everything after it."""
        path = self.path_to_leaf()
        last_cp = max((i for i, e in enumerate(path) if e["type"] == "checkpoint"), default=None)
        start = 0 if last_cp is None else last_cp
        out = []
        for e in path[start:]:
            if e["type"] == "checkpoint":
                out.append({"role": "user", "content": f"<checkpoint>\n{e['summary']}\n</checkpoint>"})
            elif e["type"] == "message":
                out.append(e["message"])
        return out

    def tree(self):
        """Text view of all branches, for a /tree command."""
        children = {}
        for e in self.entries.values():
            children.setdefault(e["parent_id"], []).append(e)
        lines = []
        def walk(pid, depth):
            for e in children.get(pid, []):
                text = e.get("message", {}).get("content") or e["type"]
                mark = " <- leaf" if e["id"] == self.leaf else ""
                lines.append(f"{'  ' * depth}{e['id']} {str(text)[:50]!r}{mark}")
                walk(e["id"], depth + 1)
        walk(None, 0)
        return "\n".join(lines)

class FileMemory:
    """A memory slot outside history: recalled into each turn as a labeled user message, saved by a tool.
    Compaction never sees it, so it cannot be summarized away (eve)."""
    def __init__(self, path=Path.home() / ".harness" / "memory.md"):
        self.path = path
    def recall(self):
        text = self.path.read_text() if self.path.exists() else ""
        return {"role": "user", "content": f"<memory slot='profile'>\n{text}\n</memory>"} if text.strip() else None
    def save(self, fact: str):
        self.path.parent.mkdir(parents=True, exist_ok=True)
        with self.path.open("a") as f:
            f.write(f"- {fact.strip()}\n")
        return "saved"

Wiring:

  • At start: Session.latest(cwd) if the user passed -c, otherwise Session.new(cwd). Rebuild state.messages from session.messages().
  • After every message: session.append("message", message=...). After compaction: session.append("checkpoint", summary=...). History before it stays in the file.
  • Add /tree and /fork <id> commands that call tree() and branch().
  • Each turn, prepend memory.recall() to the request (not to the stored history), and give the model a memory_save(fact) tool.

Stage 2 gate

  1. Start a long task, quit mid-way, resume with -c, and finish. Nothing should be repeated.
  2. Let the agent try a wrong approach, branch back, and solve it another way. Show the tree in a post.
  3. Tell the agent a preference in one session ("use pytest -q"). Start a new session and check it follows it without being told.
