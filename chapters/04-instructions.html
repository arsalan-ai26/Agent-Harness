Stage 2 · Context · Chapter 4

Instructions and context assembly

The model knows nothing about your project, your rules or today's date unless it is in the request (fact 2), and every request is paid for again (fact 4). So before the model acts, the harness decides what it sees: a system prompt, project instructions, environment facts and the names of available skills. This chapter compares how fx, Pi, eve and nanocode assemble that context, and shows the one rule all of them respect: never change the prefix mid-session. You build a context assembler that keeps the prefix stable and appends every change at the end.

Level: intermediate Time: about 20 hours with the build Needs: Stage 1 Code read at: Pi fb248c7, eve 5c52fbf, fx cbe7daf, nanocode 015cbfa
Before you start: skip check
  1. The agent changes git branch mid-session. Where should the harness tell the model?
  2. A repo has AGENTS.md at the root and another in packages/api/. When should the second one load?
  3. What is the "zero tolerance" rule for AGENTS.md?
Answers
  1. Append a small update block to the end of the latest message (user message or tool result). Rewriting the system prompt would break the prompt cache.
  2. Either at start if the session begins inside that folder, or the first time a tool touches that folder (fx attaches it to that tool result).
  3. Every line must trace back to a real agent failure; if you cannot name the failure, delete the line.

1. The layers of context

Derive the layout instead of memorizing it. Two facts pull in opposite directions. Fact 2 says the model must be told everything it needs on every call, so the request is large and mostly repeated. Fact 4 says repeated input is cheap only if it is an identical prefix: the provider caches the computation for the first N tokens and can reuse it only if those N tokens match exactly. A change at token 500 forces recomputing everything after token 500.

The resolution is to sort content by how often it changes. What never changes in a session (core instructions, tool schemas) goes first. What changes once per session (project rules, environment facts) goes next. What changes every step goes last. Then each step adds new tokens only at the end and pays full price only for those. There is a second reason the tail is the right place for news: models attend most reliably to the start and the end of their input, so a fresh update at the end is both cheap and noticed.

So a request is a stack. The top changes rarely, the bottom changes every step. Put things in the right layer and caching works for free. The rule "never edit the prefix mid-session; append the change instead" is not a style choice; it falls straight out of how the cache works.

2. Code tour

fx: an operating manual plus appended updates

src/builtins/system_prompt.md is about 1,000 words in sections: identity and context, workspace behaviour, source routing, interaction, safety. It tells the model to inspect before answering, to load named skills completely, to tell the user what failed before retrying, and to send one short update before the first tool call.

Two mechanisms keep it cache-stable. First, when cwd, git state or permission mode change, fx appends an <fx-context-update> block to the end of the message where it noticed the change; the prompt says its values replace the runtime context, and fx escapes the tag in tool output so a file cannot forge one. Second, src/builtins/context.zig notes that folder rules are not added to the session-start instructions when a later tool call reaches a new folder; they ride on that step's last tool result instead. A later turn that reaches the folder again gets a short reminder line, because "without it some models stop applying them after the turn they arrived in." fx also has per-model prompt overlays (modelPromptOverlay).

Pi: short prompt, ancestor files

packages/coding-agent/src/core/system-prompt.ts builds a short prompt from tool snippets and guidelines; users can replace it entirely. resource-loader.ts looks in each directory for AGENTS.override.md, AGENTS.md, AGENTS.MD, CLAUDE.md, CLAUDE.MD and takes the first match, so Pi reads Claude Code projects unchanged. It also handles git worktrees: a nested worktree's own AGENTS.md shadows the main repo's copy so the same rules are not loaded twice.

nanocode: deduplicated, size-capped sources

crates/core/home/src/instructions.rs loads AGENTS.override.md before AGENTS.md at each scope, caps each file at MAX_INSTRUCTION_FILE_BYTES, and skips a file whose content is identical to one already loaded with the diagnostic "included once". The pinned vendor prompts (Chapter 2) stay byte-identical across rounds and reloads; docs/memory-invariant.md lists prefix stability as an invariant.

eve: markdown plus code-computed instructions

eve's agent/instructions.md is the always-on prompt. Dynamic instructions (defineDynamic) are TypeScript functions that return text per session and can be memoized, for example to load a replaced session's transcript. After a redeploy, system-role instructions update on the next turn, while a changed user-role instruction joins the history again and an unchanged one is not re-added. That is cache-aware by design.

4. Research and the Chinese view

  • Natural-Language Agent Harnesses (Tsinghua, Mar 2026) goes furthest: harness logic itself (contracts, roles, stages, failure taxonomy, state) is written as editable natural language and executed by a shared runtime (arXiv 2603.25723). AGENTS.md is the everyday version of this idea.
  • Attention recitation. Manus rewrote a todo.md at the end of the context so the goal stays in the model's recent attention; fx's folder-rule reminder line is the same idea applied to rules.
  • Zero-tolerance AGENTS.md. Chinese practitioners popularized the rule that every line must trace to a real failure (CSDN). We adopt it: each line in our AGENTS.md gets a comment naming the failure that created it.
  • OpenAI's practice. The Codex harness-engineering team kept AGENTS.md short and used it as a map into a structured docs folder, rather than one giant file.

5. Build: a cache-stable context assembler

"""Context assembly: a stable prefix, project instructions, and changes appended at the end, never in the prefix."""
import os, platform, subprocess
from pathlib import Path

MAX_INSTRUCTION_BYTES = 32 * 1024            # Codex caps each source at 32 KiB
CANDIDATES = ["AGENTS.override.md", "AGENTS.md", "CLAUDE.md"]   # first match per directory wins (Pi, nanocode)

BASE_PROMPT = """You are a coding agent working in the user's repository.
- Inspect before you answer: read files and run commands instead of guessing.
- Read a file before editing it. Keep edits small and inside the requested scope.
- After changing code, run the relevant tests and report the result.
- If a tool fails, read the error before retrying. Do not repeat an action without new evidence.
- Ask the user only for decisions you cannot make from the repository.
Runtime facts may change during the session. When they do, a <context-update> block is appended to the
latest message; its values replace earlier ones."""

def git_root(start: Path) -> Path:
    try:
        out = subprocess.run(["git", "rev-parse", "--show-toplevel"], cwd=start, capture_output=True, text=True)
        return Path(out.stdout.strip()) if out.returncode == 0 else start
    except FileNotFoundError:
        return start

def instruction_file(directory: Path):
    for name in CANDIDATES:
        p = directory / name
        if p.is_file():
            return p
    return None

def discover(cwd: Path, home: Path = Path.home() / ".harness"):
    """Global file first, then every directory from the repo root down to cwd. Identical files load once."""
    root, files, seen = git_root(cwd), [], set()
    dirs = [home] + [root] + [root / Path(*cwd.relative_to(root).parts[:i + 1]) for i in range(len(cwd.relative_to(root).parts))]
    for d in dirs:
        f = instruction_file(d)
        if f is None:
            continue
        text = f.read_text(encoding="utf-8-sig")[:MAX_INSTRUCTION_BYTES]
        if text in seen:                     # nanocode: "identical to X; included once"
            continue
        seen.add(text)
        files.append((f, text))
    return files

def environment(cwd: Path) -> dict:
    def git(*a):
        r = subprocess.run(["git", *a], cwd=cwd, capture_output=True, text=True)
        return r.stdout.strip() if r.returncode == 0 else ""
    return {"cwd": str(cwd), "os": platform.system(), "shell": os.environ.get("SHELL", "sh"),
            "git_branch": git("branch", "--show-current") or "none"}

def system_prompt(cwd: Path) -> str:
    """Built once per session. Nothing in here may change mid-session, or the prompt cache misses."""
    parts = [BASE_PROMPT]
    for path, text in discover(cwd):
        parts.append(f'<instructions source="{path}">\n{text}\n</instructions>')
    env = environment(cwd)
    parts.append("<environment>\n" + "\n".join(f"{k}: {v}" for k, v in env.items()) + "\n</environment>")
    return "\n\n".join(parts)

class ContextTracker:
    """Appends changes to the end of the latest message (fx's <fx-context-update> pattern)."""
    def __init__(self, cwd: Path):
        self.env = environment(cwd)
        self.loaded = {str(p.parent) for p, _ in discover(cwd)}   # folders whose rules are already in context

    def update(self, cwd: Path) -> str:
        """Call after each tool batch; returns text to append to the last tool result, or ''."""
        now, notes = environment(cwd), []
        changed = {k: v for k, v in now.items() if self.env.get(k) != v}
        if changed:
            notes.append("<context-update>\n" + "\n".join(f"{k}: {v}" for k, v in changed.items()) + "\n</context-update>")
            self.env = now
        return "\n".join(notes)

    def folder_rules(self, touched_path: str) -> str:
        """When a tool first touches a folder with its own AGENTS.md, attach those rules to that tool result."""
        d = Path(touched_path).resolve()
        d = d if d.is_dir() else d.parent
        f = instruction_file(d)
        if f is None or str(d) in self.loaded:
            return ""
        self.loaded.add(str(d))
        return f'\n<instructions source="{f}" scope="{d}">\n{f.read_text(encoding="utf-8-sig")[:MAX_INSTRUCTION_BYTES]}\n</instructions>'

How to use it:

  • Call system_prompt(cwd) once at session start and store it in the state.
  • After each tool batch, call tracker.update(cwd) and append any result to the last tool result. If a tool touched a path, also append tracker.folder_rules(path).
  • Log cached_tokens / input_tokens per step (from Chapter 2). After the second step it should stay high.

Measure

  1. Write an AGENTS.md for your test repo with three rules, each tied to a failure you saw in Stage 1. Rerun the 10 tasks.
  2. Add a rule that is not tied to any failure (for example "write clean code"). Does it change anything you can measure? If not, delete it.
  3. Compare cache hit share with and without the tracker: in the "without" version, rebuild the system prompt every step.
