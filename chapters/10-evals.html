Stage 3 · Control · Chapter 10

Verification, evals and observability

A harness change that is not measured is a guess. This chapter is about three feedback loops: the agent checking its own work before it stops, you checking whether a harness change helped, and everyone seeing where time, tokens and money went. It reads eve's eval framework, Pi's paired "lift" evals, fx's 2 ms performance gate and nanocode's cost fold, then builds tracing, a cost report and a paired A/B eval runner. It closes Stage 3.

Level: intermediate Time: about 20 hours with the build Needs: Stage 2, your test tasks from Chapter 1 Code read at: Pi fb248c7, eve 5c52fbf, fx cbe7daf, nanocode 015cbfa
Before you start: skip check
  1. Your change raises the pass rate from 6/10 to 7/10 on one run. Is the change better?
  2. What is a paired comparison in agent evals?
  3. Who should decide that a task is done: the agent or the harness?
Answers
  1. Not proven. Agents are random; one extra pass on one run is noise. Repeat each task several times and compare the same tasks across both variants.
  2. Running the same tasks, the same number of times, under two variants (old and new harness), then comparing per task. Pi's evals call the difference "lift".
  3. The harness, through an external check: tests, a feature list, a reviewer. The agent's own "done" is a claim, not evidence.

2. Code tour

eve: evals that talk to the real agent

An eve eval is a .eval.ts file under evals/ run by eve eval (docs/evals/index.mdx). It sends messages to a running agent over the same HTTP API as users and records assertions: t.send(...), t.succeeded(), t.calledTool("get_weather"), t.check(turn.reply, includes("Sunny")). Tool stubs fix what tools return; a judge (src/evals/judge.ts) scores open answers; a mock model (mock-model.ts) makes fast unit tests; reporters send results to Datadog and others. In production, Agent Runs shows every session's turns, tool calls, reasoning, timing and token use in the Vercel dashboard with no instrumentation.

Pi: measure the lift of a change

packages/evals uses vitest-evals. Its documentation-lift evals run each case twice, without_docs and with_docs, in isolated Docker containers, expand cases into (case, variant, repetition) tasks (src/plan.ts), and pair the two arms to compute lift (src/report.ts). That is exactly the method for any harness change: same cases, both variants, repeated, paired. packages/telemetry defines vendor-neutral telemetry contracts with conformance tests.

fx: performance is a test too

fx's CI fails a pull request if any benchmarked command, such as fx help or fx status --json, takes over 2 ms on Linux, and release binaries must fit a size limit (benchmarks/check_budgets.py). It also benchmarks long-turn memory and approval review. /trace shows bounded compaction events in the app.

nanocode: cost as a pure fold

crates/core/cost-fold computes tokens, dollars and machine time per step as a pure function over the event log, rolled up by agent, turn, board task and commit. bin/nanocode-sim tests the memory invariants from docs/memory-invariant.md as numbers.

4. Research and the Chinese view

  • Self-verification is the biggest lever. LangChain's Terminal Bench gains came mostly from making the agent verify its work and from tracing (LangChain).
  • Harness optimization from traces. Meta-Harness gives a coding agent the raw traces, code and scores of past harness versions and lets it propose the next one; the access to raw traces, not summaries, is the key (Meta-Harness). JIT-Agent and test-time harness evolution extend this (arXiv 2608.25593).
  • Scores mix model and harness. A Sep 2026 survey proposes evaluating model, harness, environment and evaluator as four separate factors (survey).
  • Chinese view. Chinese write-ups describe harness feedback as "semantic gradient descent": natural-language feedback steers outputs the way numeric gradients steer weights (CSDN). Alibaba published Terminal-Bench Pro as a harder benchmark.

5. Build: traces, cost and a paired eval runner

"""Traces, cost, and a paired A/B eval runner: the harness's feedback loop."""
import json, shutil, statistics, subprocess, tempfile, time, uuid
from contextlib import contextmanager
from pathlib import Path

# ---- tracing: one JSONL line per span ----------------------------------------------------------
class Tracer:
    def __init__(self, path="traces.jsonl"):
        self.path, self.stack = Path(path), []
    @contextmanager
    def span(self, kind, **attrs):            # kind: "turn", "model", "tool", "compaction"
        sid, start = uuid.uuid4().hex[:8], time.time()
        parent = self.stack[-1] if self.stack else None
        self.stack.append(sid)
        rec = {"id": sid, "parent": parent, "kind": kind, **attrs}
        try:
            yield rec                         # callers add fields: tokens, cost, ok, error
        finally:
            self.stack.pop()
            rec["ms"] = round((time.time() - start) * 1000)
            with self.path.open("a") as f:
                f.write(json.dumps(rec, default=str) + "\n")

def report(path="traces.jsonl"):
    """Where did time, tokens and money go? Roll spans up by kind (nanocode's cost fold, simplified)."""
    rows = [json.loads(l) for l in Path(path).read_text().splitlines()]
    by = {}
    for r in rows:
        k = by.setdefault(r["kind"] if r["kind"] != "tool" else f"tool:{r.get('name')}", {"n": 0, "ms": 0, "tokens": 0, "usd": 0.0, "errors": 0})
        k["n"] += 1; k["ms"] += r.get("ms", 0); k["tokens"] += r.get("tokens", 0)
        k["usd"] += r.get("usd", 0.0); k["errors"] += 0 if r.get("ok", True) else 1
    return by

# ---- evals: a task is a folder with prompt.md and check.sh; the scratch repo is copied fresh each run
def load_tasks(root):
    return [{"id": d.name, "prompt": (d / "prompt.md").read_text(), "check": d / "check.sh"}
            for d in sorted(Path(root).resolve().iterdir()) if (d / "prompt.md").exists()]

def run_once(agent, task, repo):
    """agent(prompt, workdir) -> dict with steps, tokens, usd. Pass/fail comes only from check.sh."""
    work = Path(tempfile.mkdtemp(prefix=f"eval-{task['id']}-"))
    shutil.copytree(repo, work, dirs_exist_ok=True)
    t0 = time.time()
    try:
        stats = agent(task["prompt"], str(work)) or {}
    except Exception as e:
        stats = {"error": str(e)}
    ok = subprocess.run(["bash", str(task["check"])], cwd=work, capture_output=True).returncode == 0
    shutil.rmtree(work, ignore_errors=True)
    return {"task": task["id"], "pass": ok, "secs": round(time.time() - t0, 1), **stats}

def compare(agent_a, agent_b, tasks, repo, repeats=3):
    """Paired comparison: the same tasks, repeated, for two harness variants. Reports lift, not anecdotes."""
    results = {"A": [], "B": []}
    for task in tasks:
        for _ in range(repeats):                         # agents are random; one run proves nothing
            results["A"].append(run_once(agent_a, task, repo))
            results["B"].append(run_once(agent_b, task, repo))
    def summary(rs):
        return {"pass_rate": round(sum(r["pass"] for r in rs) / len(rs), 3),
                "mean_tokens": round(statistics.mean(r.get("tokens", 0) for r in rs)),
                "mean_usd": round(statistics.mean(r.get("usd", 0) for r in rs), 4),
                "mean_steps": round(statistics.mean(r.get("steps", 0) for r in rs), 1)}
    a, b = summary(results["A"]), summary(results["B"])
    per_task = {t["id"]: (sum(r["pass"] for r in results["A"] if r["task"] == t["id"]),
                          sum(r["pass"] for r in results["B"] if r["task"] == t["id"])) for t in tasks}
    return {"A": a, "B": b, "lift_pass_rate": round(b["pass_rate"] - a["pass_rate"], 3),
            "per_task_passes_A_vs_B": per_task, "runs": results}

Wiring:

  • Wrap each turn, model call, tool call and compaction in tracer.span(...) and add tokens, dollars and ok to the record.
  • Turn your 10 tasks into folders: tasks/<id>/prompt.md and check.sh. The check, not the agent, decides pass or fail.
  • Write agent(prompt, workdir) as a thin wrapper over your harness that returns steps, tokens and dollars. Make two variants (for example hooks off vs on) and call compare(A, B, tasks, repo, repeats=3).

Stage 3 gate
